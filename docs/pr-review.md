# pr-review 使用指南 — GitHub Action AI PR 审查

> 自建 CodeRabbit 替代方案：PR 打开/更新时自动用 LLM 审查 diff，发整体评论 + 行内评论线程，
> 并通过 check-run 提供合并门禁。
>
> 更新：2026-08-11（含 v2 降误报改进与行内线程）

---

## 一、实现原理

`pr-review/` 目录是一个 **GitHub composite action**，被引用时 GitHub 会把 ai-tools 仓库
克隆到 runner（`_actions/Tania-X/ai-tools/main/pr-review/`），随后按 `action.yml` 执行：

```
main.py (action 入口)
 ├─ 读环境变量: GITHUB_TOKEN / GITHUB_REPOSITORY / GITHUB_EVENT_PATH(均自动注入)
 ├─ 加载配置: gateway LLM 配置(AI_GATEWAY_* env) + 审查配置(.ai-review.yaml)
 ├─ 收集仓库上下文: AGENTS.md / README / docs / spec(约定与契约, 降低误报)
 ├─ ReviewRunner 编排:
 │    GitHub API 取 PR 信息 + 文件 diff
 │    → 过滤(ignore_paths / 生成代码) → 分批切片
 │    → 每批组装 prompt 调 LLM → 解析 JSON(文件+行号+级别+分类+依据)
 ├─ 输出: 整体评论 + 行内评论线程 + check-run(门禁)
 └─ 达到门禁级别 → exit 1(PR 变红)
```

关键点：`main.py` 会把仓库根加入 `sys.path`，从而同时复用本包与仓库根的 `gateway` 包
（GitHub 克隆的是整个 ai-tools 仓库，gateway 就在旁边）。

## 二、前提条件

| 前提 | 说明 |
|------|------|
| **ai-tools 是 public 仓库** | `uses:` 机制会克隆被引用仓库到 runner；public 免认证。若变 private，外部仓库无法直接引用 |
| **被审查仓库的 GitHub 配置** | workflow 文件 + `DEEPSEEK_API_KEY` secret + workflow 合入 main |
| **LLM 的 API key** | DeepSeek / Kimi / OpenAI 兼容端点的 key（审查的"大脑"） |

## 三、配置流程（手动）

```
① 被审查仓库根放 .ai-review.yaml(可选)
     复制 pr-review/.ai-review.yaml.example, 按需改审查重点/噪音门槛; 不建用默认

② 建 .github/workflows/ai-review.yml
     on: pull_request: branches:[main] types:[opened, synchronize]
     permissions: contents: read + pull-requests: write + checks: write
     steps: actions/checkout@v4 → Tania-X/ai-tools/pr-review@main
            with: api-key: ${{ secrets.DEEPSEEK_API_KEY }}

③ 推送 main(workflow 文件必须合入 main 才生效!)

④ GitHub 仓库 Settings → Secrets and variables → Actions
     → New repository secret: DEEPSEEK_API_KEY

⑤ 开一个目标 main 的 PR → Actions 出现 "AI Review" → 跑完出评论

⑥ (可选) 真正阻止合并:
     Settings → Branches → 保护规则 → Require status checks → 勾选 AI Review
```

模板见仓库根 `README.md` 的「接入其他仓库 (Checklist)」节。

## 四、行为说明

- **整体评论**：`## 🤖 AI 代码审查 · 第 N 次评审`，含 summary + 问题清单 + token/成本统计
- **行内评论线程**：每条可定位问题挂在 diff 对应行上（`side=RIGHT`），可直接在行上回复讨论。
  行号不在 diff 新增行集合内（如上下文行）的 issue 自动降级留在整体评论，避免 API 422
- **check-run 门禁**：存在达到 `fail_on_severity`（默认 error）级别的问题 → conclusion=failure
  （PR 变红）；AI 标记 `needs_review`（需人工确认）的问题**不计入**门禁，避免误报阻塞
- **评审次数**：`count_ai_reviews()` 按 review body 标识统计已发次数，本次 = 已有数 + 1
- **仓库上下文**：自动收集 `context_files`（默认 AGENTS.md / README / docs/** / spec/**）前 150 行，
  预算 `max_context_chars`（默认 8KB），帮助 AI 结合约定与契约判断，显著降低设计意图类误报
- **生成代码排除**：文件头含 `Generated by` / `@generated` / `DO NOT EDIT` 标记的文件自动跳过
  （orval 生成的 client.ts 等不再被审）

## 五、常见问题与坑

| 现象 | 原因 / 解法 |
|------|------------|
| workflow 不触发 | `pull_request` 事件读 **base 分支(main)** 的 workflow 定义，文件不在 main 上无效 |
| check-run 不出现（评论正常） | 漏配 `checks: write` 权限；创建失败仅告警不中断评论 |
| 报 `UnsupportedProtocol` | 空环境变量覆盖了 gateway 默认 base_url；检查是否显式传了空 `base-url` input |
| 评论只有文件名没代码 | 老版本裸 hunk 解析 bug，升级到最新 main |
| `fail_on_severity: off` | 永不拦合并，只发评论 |

## 六、配置项参考（.ai-review.yaml）

| 配置 | 默认 | 说明 |
|------|------|------|
| `review_focus` | 5 条默认 | 审查重点（进入 prompt 指令） |
| `ignore_paths` | 锁/构建/vendor 等 | glob 忽略（`**/x` 同时匹配根路径） |
| `min_severity` | `warn` | 评论输出门槛（error > warn > info） |
| `fail_on_severity` | `error` | 合并门禁级别（error / warn / off） |
| `max_files_per_batch` | 20 | 大 PR 分批切片 |
| `max_lines_per_file` | 800 | 单文件 diff 截断 |
| `context_files` | AGENTS/README/docs/spec | 仓库上下文注入文件 |
| `max_context_chars` | 8000 | 上下文预算 |
| `ignore_generated` | true | 生成代码文件头检测 |
| `show_stats` | true | 评论附带模型/token/成本 |
