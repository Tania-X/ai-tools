## 审查结论:发现问题(2 error/warn + 1 info)

### 1. nil 指针解引用,程序必然 panic —— **error**

- **位置**:`src/main.go:21`(`return getUser(id).Name`),由 `src/main.go:25`(`fmt.Println(getName("missing"))`)触发
- **问题**:`getUser` 对空 map 取键,`cache["missing"]` 返回零值 `nil`;`getName` 未判空直接解引用 `.Name`,运行时 panic。且 `main` 传入的 `"missing"` 必然不在缓存中,**每次运行都会崩溃**,`fmt.Println` 永远执行不到。
- **修复建议**:
  ```go
  func getName(id string) string {
      u := getUser(id)
      if u == nil {
          return ""
      }
      return u.Name
  }
  ```
  或按业务预期让 `getUser` 查不到时返回错误而不是裸 `nil`。

### 2. 缓存永不填充,`getUser` 恒返回 nil —— **warn**(第 1 条的根本原因)

- **位置**:`src/main.go:12`(`var cache = map[string]*User{}`)
- **问题**:`cache` 声明为空 map,全文件(也是本目录唯一文件)没有任何插入/初始化路径,`getUser` 对任意 id 都返回 `nil`。整个缓存层形同虚设——这也是第 1 条 panic "无条件触发"的根因:不是仅"missing"会崩,而是**任何 id** 都会崩。
- **修复建议**:若确要提供"按 id 查用户"语义,应预置数据(如 `map[string]*User{"alice": {Name: "Alice"}}`)或提供填充入口;否则删除这段死代码,只保留 `getName` 的判空逻辑。

### 3. 注释/文档信息丢失 —— **info**

- **位置**:`src/main.go:1-3`
- **问题**:原文件头注释明示这是 golden 测试的**基线**("无问题版本, 各场景在其上注入已知变更"),此改动将其删除并换成"提供用户查询示例.",同时删除了 `// main 是程序入口。`。在 `l3-eval` 的 golden 测试框架下,基线的"无问题"定位被破坏,且注释与实际行为(现在会 panic)已不符。
- **修复建议**:保留基线说明注释;若本文件改作真实示例,补回 `main` 的 doc 注释并让注释与实际行为一致。
